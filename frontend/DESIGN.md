# Plutus Design System

> Переиспользуемая спецификация визуального языка и dashboard-продукта Plutus.
>
> Этот файл — источник контекста для будущих UI-задач, а не просьба копировать референс пиксель в пиксель. При изменении интерфейса сначала сохраняются достоверность финансовых данных, читаемость, доступность и существующая функциональность.

## 1. Как использовать этот документ

Перед созданием нового экрана или компонента:

1. Найти соответствующий раздел и переиспользовать существующие токены.
2. Использовать существующие компоненты, утилиты и паттерны проекта вместо новой абстракции.
3. Не менять расчёты, API, маршруты, авторизацию или данные ради визуального сходства.
4. Проверить desktop, tablet и mobile-сценарии.
5. Для финансовых значений проверить длинные суммы, отрицательные значения, разные валюты и отсутствие данных.
6. Для интерактивных элементов проверить hover, focus-visible, disabled, keyboard и touch-состояния.

Если требование пользователя противоречит этому файлу, требование пользователя имеет приоритет. После согласованного изменения этот файл нужно обновить.

### Источник истины

- **Визуальные токены:** раздел 3 и JSON в конце файла.
- **Структура dashboard:** раздел 5.
- **Финансовая цветовая логика:** раздел 8.
- **Реальные CSS/React-паттерны:** соответствующий компонент в разделе 12.
- **Актуальное поведение приложения:** код важнее приблизительных размеров в этом документе.

## 2. Визуальная идея

Plutus — современный тёмный финансовый dashboard с плотной, но не перегруженной композицией.

Ключевые характеристики:

- очень тёмный графитовый холст, но не чистый чёрный;
- самостоятельные матовые карточки с тонкой границей;
- мягкие скругления без чрезмерного glassmorphism;
- лаймовый акцент для положительного движения, активных состояний и главного финансового фокуса;
- жёлтый нейтральный статус и красный негативный статус;
- важные финансовые числа визуально доминируют над вторичными подписями;
- графики являются фоном или главным визуальным слоем, но не скрывают данные;
- интерфейс должен ощущаться как дружелюбный цифровой кошелёк, а не как административная таблица.

### Приоритеты дизайна

1. Достоверные реальные финансовые данные.
2. Быстрое считывание состояния капитала и расходов.
3. Понятная иерархия: заголовок → значение → пояснение → действие.
4. Предсказуемое поведение на узком экране.
5. Читаемость длинных русских подписей и денежных значений.
6. Минимум декоративных элементов, которые не несут смысла.

### 3.3 Типографика

Основное семейство задаётся глобально:

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif;
```

Рекомендуемая иерархия:

| Роль | Размер | Вес | Дополнительно |
| --- | --- | --- | --- |
| Page title | `30–40px` | `700` | Плотный tracking, line-height около `1`. |
| Card title | `15–18px` | `600` | Хороший контраст, без лишней декоративности. |
| Hero amount | `40–56px` | `700` | `tabular-nums`, короткий line-height. |
| Chart value | `13px` или больше при узком экране | `400–600` | Не уменьшать область графика ради подписи. |
| Body | `13–15px` | `400–500` | Основной читаемый текст. |
| Secondary | `11–13px` | `400–500` | Только для дат, пояснений и вторичных деталей. |
| Small action | `12–14px` | `500–600` | Должен оставаться читаемым при масштабировании. |

Денежные значения:

- использовать `tabular-nums` для колонок и сравнений;
- форматировать через существующие `formatCurrency` или `formatCurrencyCompact`;
- длинные значения сокращать локализованно, а не обрезать случайным CSS;
- отрицательное значение должно сохранять знак;
- для русского языка использовать понятные сокращения `тыс.` и `млн`;
- не уменьшать шрифт до нечитаемого размера только ради того, чтобы вместить сумму.

## 4. Оболочка приложения и responsive

### 4.1 Desktop shell

- Sidebar фиксирован слева и меняет ширину между раскрытым и свернутым состоянием.
- Основной контент учитывает CSS-переменную `--sidebar-width`.
- Dashboard центрируется и на широком экране получает ограниченную максимальную ширину.
- На desktop у контента есть боковые поля; на mobile не добавлять лишнее сжатие.

Текущий паттерн dashboard-обёртки:

```tsx
<div className="mx-auto space-y-5 pb-10 md:max-w-[1440px] md:px-4 xl:px-8">
  {children}
</div>
```

### 4.2 Breakpoints

| Диапазон | Поведение |
| --- | --- |
| `< 768px` (`max-md`) | Одна колонка, sidebar скрыт, mobile navigation, панели складываются вертикально. |
| `>= 768px` (`md`) | Sidebar и двухколоночные dashboard-блоки разрешены. |
| `>= 1024px` (`lg`) | Увеличиваются внутренние padding некоторых карточек и доступна более плотная композиция. |
| `>= 1280px` (`xl`) | Максимальная ширина dashboard и расширенные правые колонки. |

Обязательные правила:

- не заставлять пользователя горизонтально прокручивать основной экран;
- длинные заголовки и имена счетов должны сокращаться через `truncate` или переноситься в подходящем месте;
- действия не должны исчезать при сжатии;
- плотность desktop не должна переноситься на mobile без проверки touch-размера;
- график может занимать свободное место, но правая граница фонового графика не должна заходить под разделитель панели статистики.

## 5. Актуальная структура dashboard

Порядок блоков на странице:

```text
Заголовок dashboard + фильтр периода
Статус источника данных
Empty state, если нет счетов
Общий капитал
Быстрые действия
┌ Динамика капитала ┐ ┌ Расходы по категориям ┐
└───────────────────┘ └───────────────────────┘
┌ Последние операции (13) ┐ ┌ Ваш капитал растёт! ┐
                           ├─┤ Месячные лимиты      ├
                           ├─┤ Обязательные платежи ├
                           └─┤ Цели                 ┘
```

На mobile эта схема превращается в одну последовательную колонку.

### 5.1 Заголовок и фильтры

- Заголовок страницы заметный, но не конкурирует с карточкой капитала.
- Период и уведомления находятся справа на широком экране.
- На узком экране controls переносятся под заголовок.
- Период должен быть явно виден и влиять на график и расходы.

### 5.2 Общий капитал

Главная карточка dashboard:

- фон — тёмный градиент, статусный оттенок допускается только мягко;
- внутри есть реальный 31-дневный график-фон;
- фоновой график начинается от `left-0`;
- горизонтальная маска задаётся в пикселях:

```tsx
const mask =
  "linear-gradient(90deg, transparent 0px, transparent 160px, " +
  "rgba(0,0,0,.35) 240px, rgba(0,0,0,.75) 330px, " +
  "black 420px, black 100%)";
```

- линия, заливка и glow проходят через одну маску;
- отдельная затемняющая подложка под текстом не нужна;
- график должен заканчиваться перед вертикальным разделителем статистики;
- text block располагается поверх графика и может быть немного поднят для визуального баланса;
- справа компактная кликабельная статистика: свободные деньги, наличные, инвестиции, накопления;
- `Наличные` не должны повторно входить в `Свободно`.

### 5.3 Финансовый цветовой статус

Цвет карточки и объединённого графика определяется не процентом от самого капитала, а денежным потоком:

```text
Средние месячные расходы = среднее расходов по доступным месяцам
Чистый поток = доходы - расходы
Нормализованный поток = чистый поток / длительность периода в месяцах
Порог = средние месячные расходы × 0.035
```

Статусы:

| Условие | Статус | Цвет |
| --- | --- | --- |
| `нормализованный поток < -порог` | Negative | `#F27683` |
| `-порог <= поток <= +порог` | Neutral | `#F2C45E` |
| `нормализованный поток > +порог` | Positive | `#C0F05C` |

Правила расчёта:

- `income` увеличивает поток;
- `expense` уменьшает поток;
- `transfer` между своими счетами не считается доходом или расходом;
- отрицательный баланс сам по себе не заменяет анализ потока;
- при отсутствии истории расходов статус нейтральный;
- расчёты выполняются в валюте пользователя через `convertCurrency`;
- изменение стоимости инвестиций не следует считать обычным доходом без отдельной модели инвестиционной доходности.

Применение цвета:

- `Общий капитал`: фон карточки, линия, fill, glow, tooltip cursor и active point;
- `Динамика капитала` в combined mode: линия, fill, glow/active point, bar fill и cursor;
- отдельные серии счетов: сохраняют собственные цвета для различимости, а не получают один общий статусный цвет.

### 5.4 Динамика капитала

Карточка графика:

- высота около `330px` на desktop;
- тёмная карточка с `20px` радиусом;
- заголовок и выбранный период сверху;
- chart area занимает оставшееся пространство;
- подписи оси значений должны быть читаемыми (`13px` ориентир);
- сама область графика не должна уменьшаться из-за увеличения шрифта оси;
- tooltip показывает дату, значение, изменение, процент и событие, если оно есть;
- в separate mode легенда показывает реальные названия счетов;
- легенда занимает минимум вертикального пространства, остаётся в одну строку с горизонтальным overflow и уменьшается при большом количестве счетов;
- название счета должно задаваться через `name`, а не восстанавливаться только из числового `dataKey`.

Поддерживаемые режимы:

- `Area`: основной режим для динамики;
- `Bar`: сравнение значений по дням;
- `Line`: чистая линия без заливки;
- `combined`: общий капитал одной серией;
- `separate`: отдельная линия/area/bar на каждый счет.

### 5.5 Расходы по категориям

Кольцевой график показывает только реальные расходы выбранного периода.

- размер donut не меняется ради длинной суммы;
- текст в центре центрируется внутри `innerRadius`;
- сумма форматируется адаптивно и локализованно;
- большие значения сокращаются:

```text
1 774,66 $  ->  $1,77 тыс.   (английская локаль)
143 070 ₽   ->  143 тыс. ₽   (русская локаль)
1 250 000 ₽  ->  1,25 млн ₽
```

- для сумм от `100` тысяч в сокращённой части убираются лишние копейки;
- при длинной строке используется меньший размер (`text-base`), но не меняется площадь графика;
- подпись `Всего` остаётся под суммой;
- легенда категорий находится рядом на desktop и складывается ниже на mobile;
- название категории должно быть обрезано аккуратно, а полное значение доступно через `title` или tooltip.

### 5.6 Последние операции

- показываются 13 последних транзакций, сортировка по дате убыванию;
- каждая строка содержит иконку типа, описание/категорию, дату и сумму;
- расходы и доходы различаются иконкой и цветом, но смысл не передаётся только цветом;
- суммы имеют знак `-` или `+`;
- конвертированное значение показывается дополнительно, если валюта транзакции отличается от валюты приложения;
- список должен оставаться читаемым при длинных описаниях;
- ссылка `Все` ведёт на `/transactions`.

### 5.7 Правая колонка под динамикой

Порядок карточек фиксирован:

1. **Ваш капитал растёт!** — короткая интерпретация движения капитала и ссылка на аналитику.
2. **Месячные лимиты** — лимит, процент, progress bar, потрачено и полный лимит.
3. **Обязательные платежи** — повторяющиеся расходы с отметкой оплаты, сроком и действием оплаты.
4. **Цели** — прогресс цели, процент, текущая и целевая сумма.

`Месячные лимиты` и `Цели` должны выглядеть идентично:

- одна карточная поверхность;
- `rounded-[1.5rem]`, border, `bg-card`, padding около `20px`;
- заголовок `18px`, `font-semibold`;
- элементы вертикально через `space-y-3`;
- процент справа сверху;
- progress bar высотой около `8px`;
- текущая сумма слева снизу, целевая справа снизу;
- без сетки, которая раздвигает карточку по горизонтали.

## 6. Компоненты и поведение

### Карточка

Базовая карточка:

```tsx
<div className="rounded-[1.5rem] border bg-card p-5 text-card-foreground">
  ...
</div>
```

Для новых карточек не добавлять тяжёлую тень, если она не нужна для иерархии. Внутренние строки могут использовать `bg-muted/50` или `bg-background/50`.

### Кнопки

- основные действия — заметный accent, но не каждая кнопка должна быть лаймовой;
- вторичные действия — ghost/outline;
- иконка без текста допустима только при понятном `aria-label` и `title`;
- keyboard focus всегда видим через `focus-visible:ring`;
- disabled должен менять контраст и запрещать действие, а не только скрывать его.

### Ссылки и hover

- карточки статистики остаются `<Link>`, если вся строка кликабельна;
- hover должен быть мягким (`bg-white/[0.025]` или близкий токен);
- hover не должен менять геометрию строки;
- focus-visible важнее декоративного hover.

### Empty states

Empty state должен объяснять:

1. чего не хватает;
2. почему блок пуст;
3. какое следующее действие доступно.

Не заполнять пустые финансовые блоки выдуманными нулевыми событиями или демонстрационными операциями.

## 7. Доступность и устойчивость

- Контраст основного текста и суммы должен быть достаточным на фоне карточки.
- Все иконки, которые являются кнопками, получают доступное имя.
- Таблицы, списки и графики не должны быть понятны только по цвету.
- Tooltip не является единственным местом для критического финансового значения.
- Клавиатура должна достигать фильтров, ссылок, легенды и действий.
- Учитывать `prefers-reduced-motion`: анимации графиков короткие и не должны быть обязательными для понимания.
- Длинные названия категорий, счетов и транзакций не должны ломать сетку.
- При `currency !== defaultCurrency` показывать исходную и/или конвертированную сумму согласно паттерну компонента.
- Не маскировать отрицательные суммы только красным цветом — сохранять знак и текстовую индикацию.

---

## 8. Что нельзя делать

- Не добавлять вымышленные балансы, доходность, транзакции или события.
- Не менять финансовые формулы ради красивой линии.
- Не считать перевод между своими счетами доходом или расходом.
- Не показывать инвестиционный рост как обычный зарплатный доход без явной модели.
- Не использовать случайные значения для заполнения графика.
- Не растягивать легенду так, чтобы она уменьшала или ломала chart area.
- Не обрезать сумму без локализованного и предсказуемого правила.
- Не делать весь экран плотнее на mobile ради desktop-референса.
- Не добавлять новую зависимость для простой визуальной задачи.
